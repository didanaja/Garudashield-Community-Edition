# GarudaShield Demo Edition — Full-Stack Development Prompt

Act as a senior full-stack engineer specializing in Go, Next.js, network security, and modern SaaS dashboard development.

Build a standalone project called **GarudaShield Demo Edition**, a lightweight educational demonstration of a multi-layer reverse proxy and web protection system. This project will be presented in a cybersecurity competition, where judges may inspect the source code.

The project must have its own implementation and must not require, copy, expose, or depend on the proprietary source code of the original GarudaShield engine.

## 1. Technology Stack

**Backend and protection engine**
- Go (Golang), using a clean and modular architecture.
- Go standard library wherever practical.
- HTTP reverse proxy using `net/http/httputil`.
- Redis-compatible storage interface, with an in-memory implementation for local demonstrations.
- REST API with versioned routes under `/api/v1`.
- Structured logging, request IDs, configurable timeouts, and graceful shutdown.
- Unit tests for the security middleware and API endpoints.

**Frontend**
- Next.js with App Router.
- TypeScript.
- Tailwind CSS.
- Reusable React components.
- Responsive design for mobile, tablets, laptops, and desktop screens.
- Use a lightweight chart library only when actual chart data is available.

## 3. Go Demo Protection Engine

Implement a real but deliberately limited demonstration engine with the following modules:

### A. Reverse Proxy
- Forward HTTP requests to one explicitly configured upstream server.
- Use Go's standard reverse proxy implementation.
- Validate upstream configuration and reject invalid destinations.
- Configure request timeouts, response-header timeouts, and maximum request body size.
- Remove or overwrite untrusted forwarding headers.
- Prevent arbitrary upstream selection by clients.
- Never expose internal network destinations or infrastructure details through error responses.

### B. Layer 7 Request Evaluation
Implement a small, explainable rule engine that demonstrates:
- HTTP method allowlisting.
- Maximum URL and request-header sizes.
- Request body size limits.
- Basic request-rate limiting.
- Detection of a few clearly documented suspicious request patterns.
- Configurable allow and deny rules.
- Safe handling of malformed requests.

Do not claim comprehensive WAF or OWASP Top 10 protection. Document that the pattern matcher is demonstrational and cannot replace a production-grade security engine.

### C. Layer 4 Educational Module
Provide a safe educational module that explains transport-layer protection concepts and reports locally observable connection or server metrics.

Do not implement a public-facing TCP/UDP scrubbing network, packet-flood mitigation infrastructure, distributed filtering network, or high-capacity DDoS defense. Clearly distinguish HTTP application-layer controls from genuine network-layer mitigation.

### D. Rate Limiting
- Implement a per-client token bucket or sliding-window limiter.
- Trust client IP forwarding headers only when the immediate proxy is explicitly configured as trusted.
- Otherwise derive the client address from the connection.
- Return HTTP 429 with a suitable `Retry-After` header when a limit is exceeded.
- Use bounded in-memory storage and expiration to avoid unbounded memory growth.
- Explain that a single-process limiter is not a distributed rate-limiting solution.

### E. Fail-Closed Evaluation
- Add a configurable evaluation time budget.
- If the security evaluation cannot complete within its permitted budget, reject the request safely.
- Never forward a request merely because the evaluation timed out.
- Clearly distinguish an evaluation timeout from an upstream timeout.
- Ensure all timeout paths terminate predictably.

### F. Health and Metrics
Implement:
- `GET /healthz` for basic process health.
- `GET /readyz` for readiness checks.
- `GET /api/v1/status` for component status.
- `GET /api/v1/metrics` for actual local demonstration metrics.
- `GET /api/v1/rules` for the active demo rules.
- `GET /api/v1/logs` for recent sanitized security events.

Metrics may include requests evaluated, allowed requests, blocked requests, rate-limit events, evaluation timeouts, and upstream errors.

Metrics must be generated by real backend activity. Do not invent attack counts, mitigation percentages, uptime, or latency improvements.

## 4. Next.js Dashboard Integration

Connect the frontend to the Go API through a configurable API base URL.

Implement:
- Live component health polling with sensible intervals.
- Loading, healthy, degraded, and offline states.
- A dashboard displaying real request metrics.
- Recent security event logs with timestamps and verdicts.
- A readable rules overview.
- An upstream configuration page restricted to authorized administrators.
- A settings page for demo rate limits and request-size limits.
- A documentation page explaining the architecture and limitations.
- A login interface and protected dashboard routes.

Never treat frontend-only route protection as authorization. Enforce all permissions on the backend.

If authentication is implemented, use secure session handling, password hashing, CSRF protection where applicable, secure cookie settings, login rate limiting, and authorization middleware. Do not ship hardcoded production credentials.

## 5. API and Security Requirements

- Validate all inputs on the server.
- Apply restrictive CORS rules.
- Use parameterized queries if a database is introduced.
- Prevent SSRF by restricting upstream configuration and blocking prohibited destinations.
- Prevent open-proxy behavior.
- Avoid leaking secrets, stack traces, internal IP addresses, or filesystem paths.
- Add request size limits and safe error handling.
- Keep secrets in environment variables.
- Include `.env.example` with placeholders only.
- Add security-focused unit and integration tests.
- Run the frontend and backend with separate development commands.
- Use explicit configuration for trusted proxies and permitted upstreams.
- Document remaining risks and production-hardening requirements.
